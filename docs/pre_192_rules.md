# 文件进入 192 存储前的处理规则（待业务确认版）

本页记录邮件附件进入平台、分流、核对及生成 192 待存储任务的规则。它不授权系统改写飞书 DMR 清单，也不改变 192 的目录和写入凭据。规则分为“已确认”“待确认”；待确认项不能据推测自动落盘。

## 1. 收信与批次

| 步骤 | 规则 | 状态 |
| --- | --- | --- |
| 邮件筛选 | 收信关键词、发件人、邮箱/文件夹等作为可配置条件；不能把现有“建筑”关键词直接用于新场景。 | 待确认具体条件 |
| 附件获取 | 同一封邮件的附件组成一个业务批次，下载到临时目录；记录邮件 ID、主题、发件人、收信时间、附件名与校验值。处理后清理临时目录。 | 已有脚本基础能力 |
| 压缩包 | 保留原始压缩包与邮件的关联；可安全解压的格式逐个提取文件。`.7z`、`.rar` 的解压能力需另行验证，不能把未解压成功误记为“全部入库”。 | 待验证 |
| 重复接入 | 同一邮件附件按邮件 ID + 附件 ID 去重；部分附件已处理时，提示人工核对，不能重新拆散为另一个批次。 | 已实现 |

## 2. 附件分流（先于通用字段提取）

| 类型 | 识别依据 | 平台处理 | 进入 192 前的门禁 |
| --- | --- | --- | --- |
| DMR 文件转移清单 | 附件文件名以“DMR文件转移清单”开头，可带 ECN 前缀；必须是有效 `.xlsx`。 | 走转移清单专用通道；不要求主体、型号、资料类别或版本，也不当成 BOM。 | 从文件名括号内的编号提取完整 `YYYYMMDD` 日期，日期无效或格式不符时停下核对；检查同名冲突。 |
| 首次 BOM 发放 | 邮件主题/正文明确为新增或首次量产 BOM，附件与正文中的 BOM 编号能够核对。 | 作为 BOM 首发批次；BOM、转移清单及其他附件分别保留同一邮件关联。 | 不能仅凭主题给出 BOM 版本；核对正文表格或文件内容中的编号、版本、转移日期；缺失或冲突时人工确认。 |
| ECN 发放 | 邮件主题/正文明确为 ECN/工程变更，带 ECN 编号。 | 作为变更批次；保留此邮件所有附件的整体关系，不把材料编码当 BOM 编号。 | 正文提及的 BOM 编号、变更范围与附件逐项核对；没有新 BOM 版本时保持待确认，不从材料名 `V1` 推断 BOM 版本。 |
| 其他受控资料 | 不符合上述专用类型。 | 走现有 BOM / 软件 / 工艺等资料解析与人工核对通道。 | 文件名、正文、文件内容可互作证据；冲突时人工选择，不强行自动归档。 |

一封邮件可以同时包含转移清单和 BOM/ECN 资料。**转移清单只按自身规则归档；其他附件保持同一邮件批次继续核对。** 不应让转移清单进入通用“补字段”面板。

## 3. 转移清单日期和冲突规则

1. 以文件名括号中的转移单编号前八位完整日期为准。例如 `DMR文件转移清单（BW-2026100801-深圳由莱）.xlsx` 使用 `2026-10-08`，目标相对路径为 `Y-2026/DMR-2026-10/原文件名`。不以邮件收信日、上传日、表内其他转移日期代替。
2. 写入前验证电子表格结构与完整文件校验值。同一路径同名且内容相同：显示“已存在，未重复写入”和目标位置；同名内容不同：保留原件、新件留在平台待人工核对，不覆盖。
3. 平台展示目标 192 路径、实际存储状态和回执。只有服务端成功写入后才显示“已写入”，暂存或冲突不能显示为成功。
4. 转移清单归档后，页面醒目提醒文控检查对应 DMR 清单；跳到“DMR 清单”功能。系统提供候选链接和可能的修改位置，不自动改飞书单元格。没有找到具体条目也应显示已找到的候选清单。

## 4. BOM 首发与 ECN 的待存储规则

| 场景 | 已确认的处理原则 | 尚需业务确认，确认前不自动落盘 |
| --- | --- | --- |
| BOM 首发 | 首次发放的 BOM 单独成组；邮件正文表格可提供文件名称、编号、版本、份数、转移日期；同邮件转移清单按第 3 节独立处理。 | “首次”判定标准、首发文件夹的准确 192 路径、一个 BOM 邮件里多个文件/版本如何组织。 |
| ECN 变更 | ECN 不是首次发放；同一邮件所有附件保留为同一变更包，按 ECN 编号关联；同邮件转移清单按第 3 节独立处理。 | ECN 包的准确目标根目录及年/月/编号层级；是否包含转移清单的副本；附件缺失、重名、补发时如何处理。 |
| DMR 清单提醒 | 一份文件可能对应多份清单，全部候选均提醒文控核对；清单按主体、项目类别、产品型号及文件编号/名称寻找。 | 正文“添加到所有成品 BOM”之类宽泛范围，具体涉及哪些产品/清单，需文控确认。 |

## 5. 示例核对点

- `BOM发放（W20冷凝舱_5弹丽驻兰礼盒_新国标 成品）`：邮件正文列出 BOM `11W2002C15B`、版本 `20261015`、转移日期 `2026/10/19`；转移清单附件 `DMR文件转移清单（JJ-2026101901-深圳金茉）.xlsx` 独立按 `2026-10-19` 分档。BOM 的主体、产品和清单链接必须与正文或附件再核对。
- `深圳由莱-ECN（2026100005）`：正文涉及 BOM `11JM204C16B`、`11JM204C15B`；材料编码 `7600000029B` 不是 BOM 编号，材料名 `V1` 不是 BOM 版本。附件保留为一个 ECN 包；转移清单 `DMR文件转移清单（JJ-2026102202-深圳由莱）.xlsx` 独立按 `2026-10-22` 分档。

## 6. 验收检查

1. 在同一封测试邮件里放转移清单和其他附件，验证清单不进入通用字段补录，其余附件仍能在同一邮件批次核对。
2. 用合法日期、无效日期、同名同内容、同名不同内容分别测试；核对 192 目标路径与平台回执一致。
3. 用 BOM 首发和 ECN 两封样例邮件检查编号/版本提取证据；缺证据时进入人工核对，不能推断落盘路径。
4. 文控从上传结果直达待更新 DMR 清单，逐项人工完成修改；平台只记录提醒和人工确认，不宣称验证了飞书内容。
