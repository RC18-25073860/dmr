# 单实例部署与验收

本交付采用 Linux + Python 3.12 + Node/npm 构建 + 单实例 FastAPI/SQLite。不是多机高可用版本；不启动多个 worker，不把 SQLite 放到 NAS 共享盘。192 只作为同步目标。

1. 部署代码至 /opt/dmr，创建专用 dmr 系统用户；运行 bash scripts/setup.sh。
2. data 为持久目录，代码升级仅覆盖发布清单中的文件，禁止删除/替换 data。可以将独立磁盘挂载至 /opt/dmr/data；数据路径必须在项目目录内。旧代码保存在独立版本备份，绝不打包真实数据与配置分发。
3. 先用回环 local 模式在服务器初始化正式管理员；不要搬运演示账号数据库。初始化完成后停止 local 服务。
4. 将 dmr.env.example 私密复制到 /etc/dmr/platform.env，填写真实域名、生成的 NAS 凭据加密密钥；文件属主 dmr，权限600。密钥须独立受控备份，丢失后不能解密192账号。不要复用演示令牌；10年有效期不代表凭据不会失效或可公开。
5. nginx 模板填入实际证书、域名后 nginx -t；确认生产环境白名单、Secure Cookie、初始化关闭。平台只绑定127.0.0.1，外部统一HTTPS。
6. 安装 dmr.service（单实例）。配置日常日志轮转、磁盘容量/服务异常告警；检查 systemctl status 与 journalctl。模板不会自动修改系统配置。
7. 服务器使用专门的飞书读取身份，安装lark-cli并在 dmr 服务用户下授权。用户浏览器的飞书登录仅负责打开链接，不授予服务器权限。平台不按时间自动扫描；打开工作台或 DMR 清单页面、主动刷新、发起清单查询和文控全局扫描时，按需只读更新飞书目录和清单链接。定位条目时按需读取对应清单单元格；不会回写云端。授权过期或网络失败时保留上次成功快照，并显示失败状态；下次使用时可再次尝试。
8. 配置邮件脚本的受控JSON，地址使用正式HTTPS，单独配置mailbox/token/state_file/关键词。先 dry-run，再做一封已授权测试邮件接入。确认没有旧定时任务重复运行后才启用邮件timer。不要清空processed记录。
9. 192填写真实HTTPS地址、CA、worker token，逐个配置上传人192账号及目录映射。先只读核对，再使用指定测试目录验证上传/重试；绝不以本地mock测试代替真实NAS验收。目录新建需文控确认。
10. 备份：停止平台、NAS worker、邮件和目录任务；使用 backup.py 创建全data快照。另行备份 /etc/dmr 密钥配置。恢复只到全新目录，校验完整性后再切换；禁止覆盖正在运行的数据目录。旧版未安装运行锁时必须先通过服务管理器确认已停止。

## 正式验收待填写
- 域名/证书/服务器/责任人：待IT提供。
- 飞书读取账号及范围：待确认；不同平台用户不应超出获批的共享范围。
- 192测试目录/账号权限：待提供，尚未真实联调。
- 备份周期、保留天数、异地副本、RPO/RTO与恢复责任人：待确认。
- 并发用户数、最大文件量、响应时间指标：待确定，未通过生产负载验收。
- 各类文件编号来源、版本字段、共用范围：按业务规则确认表由文控确认。

## 192同步后误归档
平台保持阻止直接迁移的保护。管理员先暂停该任务/确认NAS实际路径、下载核对原件和哈希，由有权限人员处理NAS位置；真实迁移/回滚工作流验收前不要直接改数据库绕过保护。

NAS 服务还需单独启动 `dmr-nas-reader.service`，worker 负责上传，reader 负责下载。平台 `DMR_NAS_SYNC_TOKEN` 与 worker 的 `DMR_NAS_WORKER_TOKEN` 必须一致。reader 使用受信 HTTPS 证书，证书/私钥及自定义 CA 路径须在 `/opt/dmr` 内，私钥仅服务账号可读。平台 `DMR_NAS_READ_BASE_URL` 填 reader 的 HTTPS 地址；由 IT 限制 reader 端口只供公司内网访问。
